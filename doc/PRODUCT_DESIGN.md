## 1. 产品合同

**身份。** Veil 是可公开分发的 Windows 屏幕保持关闭工具：用户按物理屏决定关还是开，直到主动恢复。它不是系统熄屏快捷方式，不用黑色覆盖层冒充关屏，也不承诺面板断电。

**用户能做什么。** 托盘常驻（首次从开始菜单或安装目录的 `Veil.App.exe` 手动启动；可在面板打开开机自启）。单击托盘打开小面板，只列出已连接物理屏。关面板或最小化都退回托盘：不占任务栏，也不出现在 Alt-Tab；只能从托盘再打开。每块可单独保持关闭、单独恢复。允许同时关多块。紧急热键恢复全部。虚拟屏不出现在列表中。

**关屏何时允许。** 操作完成后必须仍有一条活动输出路径。

- 若关完后仍剩至少一块活动物理屏：走原生 CCD，清除目标路径的 ACTIVE。若被关的是主屏，允许把留下的源模式挪到桌面原点 `(0,0)`。
- 若用户要关光全部物理屏：先启用已签名 MTT 辅助虚拟输出（默认禁用，按需启用），确认出现一条活动虚拟路径后，再停全部物理路径。没有设备时，面板确认后安装再启用；本机已有同一硬件 ID 的 MTT 则接管，不重装第二块。
- 不使用向日葵、GameViewer 等其它虚拟屏作为退路，也不把它们列入可关目标。同一 MTT 设备可以接管，不是「别人装过就永远不用」。

**成功标准。** 被关的物理屏持续不显示桌面内容；普通键鼠输入不会解除保持关闭。留下的屏可继续使用。拓扑切换瞬间允许闪一下。系统状态检查与物理观察共同通过才算验收；API 返回成功不能单独算通过。面板待机或断电按设备记录，不作为全部设备必达项。

**首版不做。** 临时关闭、系统熄屏入口、把虚拟屏当作可关目标、跨重启自动再关、黑色覆盖层、自研显示驱动、精确还原窗口布局、不经确认静默安装驱动、启用测试签名、防睡眠（P1，独立选项，默认不改电源计划）。

**睡眠与重启。** 重启后保持关闭要求清空，屏幕按系统结果亮着。睡眠唤醒后重新枚举：原保持关闭的物理屏仍连接、且仍能留下一条活动路径（另一块物理屏或按需辅助输出）时，尝试把仍有效的要求再打上；否则结束保持关闭，说明原因，屏幕按系统结果亮着。再关失败必须停手并告诉用户，禁止循环 apply。

## 2. 运行时架构

采用按需路径引擎，两个进程。

**界面进程。** 托盘、小面板、开机自启开关；向引擎发送「关这块 / 开这块 / 恢复全部」。退出时必须先请求恢复，不能把恢复责任只留在即将结束的界面进程里。

**独立恢复进程。** 注册紧急热键 `Ctrl+Alt+Shift+F10`；父进程退出后仍回放保存的拓扑；睡眠唤醒后按合同尝试再关或失败即停。关屏前必须确认该进程就绪且热键注册成功，否则拒绝关屏。该进程自身崩溃不在保证范围内。人工兜底为 `Win+Ctrl+Shift+B`，仍无画面再重启。不把热键写成任意异常下都有效。

**能力引擎。** 每次操作先枚举活动路径，只把物理屏交给 UI。

1. 「关这块」：若停用后仍有活动物理路径，VALIDATE 通过才 apply；必要时 `adjustedOrigin`。VALIDATE 非 0 或剩余活动路径为 0 则不 apply。
2. 「关这块」将使物理路径变为 0：没有辅助设备则先确认安装（或接管已有 MTT），再启用，确认活动虚拟路径存在，然后停物理路径。安装或启用失败则不 apply，物理屏保持原状。
3. 「开这块」只恢复该物理屏，其它保持关闭要求仍有效（该组合尚未按产品闭环验收）。
4. 「恢复全部」与紧急热键：解除全部要求，回放仍适用的已保存配置；设备已变则恢复当前可用配置，不硬套失效布局。

**状态。** 每块物理屏区分用户要求（开启 / 保持关闭）与已确认（已显示 / 已关闭 / 处理中 / 失败 / 未知）。失败不得显示为已关闭。拓扑变化（拔插、辅助输出消失、睡眠）后重新识别。

**持久化。** 不使用 `SDC_SAVE_TO_DATABASE`。不跨重启保存关闭要求。

## 3. 安装、失败与生命周期

**安装。** 安装器写入程序，并**始终**带上已校验的 MTT 驱动文件。默认同时安装设备（禁用）。用户这次不同意装设备时，文件仍留下，以后可在面板安装。明示这是显示驱动，用于关光全部物理屏时留下一条活动路径；需同意与 UAC。不开测试签名，不经确认不装设备。向日葵 / GameViewer 不借用。本机已有同一 `Root\MttVDD` 则接管并写入所有权，不重装第二块。装完不自动开机自启、不自动关屏。

**首次关光全部物理屏。** 已有设备则说明将启用辅助输出。没有设备、但找得到已校验驱动包（安装目录或开发用 `installer/payload`）则说明将**安装并启用**。已有未登记的同一 MTT 则说明将接管并启用。失败则所有物理屏保持原状。没有驱动包才禁用最后一块的保持关闭。

**失败。** 关屏、追加关闭、单屏恢复或 VDD 克隆失败后，结束本轮全部关闭要求并尝试一次恢复，不自动重复消费请求。恢复失败或状态未知时，保留仍可用的热键和“恢复全部”，只有用户明确重试才再次执行恢复。恢复进程崩溃后保留失败上下文，启动恢复专用进程重试；不得继续显示过期心跳。没有确认活动物理输出时保留辅助 VDD。

**拔插。** 拔掉的屏标记断开，不再对它重试。新插入的屏默认开启，不继承关闭要求。同一运行期内能可靠识别的原设备，可重新应用仍有效的要求。

**退出与卸载。** 正常退出先解除全部保持关闭并恢复物理屏；恢复失败则报告，不默默退出。卸载同样先恢复，再禁用并删除所有权清单里的辅助 VDD。

## 4. 小面板

**托盘。** 单击打开面板。右键：打开面板、恢复全部、退出。关闭或最小化面板退回托盘，不占任务栏和 Alt-Tab。第二实例唤醒已有面板，不新开窗口。存在保持关闭或处理中时，图标与空闲可区分。不把会消失的气泡当作唯一反馈。

**面板内容。** 当前已连接物理屏：可区分名称、内置或外接、已确认状态、该屏此刻是否允许保持关闭。每块一个保持关闭 / 恢复。底部：恢复全部、开机自启（默认关）、紧急热键说明；没有辅助设备时另有「安装辅助输出」。热键注册失败必须在面板可见，不得写「可用」。

**文案。** 虚拟屏不出现。不能关时写原因（恢复进程未就绪、热键未注册、缺少驱动包、辅助输出未能安装或启用等）。未通过验收的能力可以有入口，失败必须如实显示，不得提前标成「已关闭」。不要用「没有自带 VDD」把可安装的情况写成死路。

**不做。** 临时关闭、虚拟屏开关、显示配置档案、窗口布局预览。卸载与驱动移除走系统「应用和功能」。

## 5. 边界与发布规则

公开材料必须分开写：产品要求、实现选择、已落地能力。日常预览可用不等于全 Windows 兼容，也不等于已发布。

能力检测失败则禁用并说明。没有第二活动目标、且无法安装或启用辅助输出时，拒绝关最后一块物理屏。API 返回成功不能单独算通过。

不得把未测 GPU、Windows 10 或 ARM 写入支持列表。

## 6. 已锁定选择

| 项 | 选择 |
| --- | --- |
| 产品定位 | 可公开的完整设计，不是个人实验室工具 |
| 虚拟屏对用户 | 隐藏依赖，界面只列物理屏 |
| 虚拟路径何时活动 | 按需：已有第二物理屏走原生；关光全部物理屏才启用 |
| 同时关几块 | 可同时关多块，只要留下一条活动路径 |
| 恢复粒度 | 每块可单独恢复；紧急热键恢复全部 |
| 临时关闭 | 首版不做 |
| 睡眠 / 重启 | 重启不恢复要求；睡醒尝试再关，失败则结束并说明 |
| 虚拟驱动归属 | 用已签名 MTT 辅助输出：随应用带文件，安装时或面板装设备，已有同一硬件 ID 则接管。不用向日葵 / GameViewer |
| 日常形态 | 托盘常驻，单击打开小面板；关面板退回托盘 |
| 开机自启 | 默认关，面板里可开 |
| 架构 | 按需路径引擎 + 独立恢复进程 |
| 实现栈 | Rust（x64 MSVC）+ egui 小面板 + 原生托盘；传统 WiX 安装包；首版含辅助虚拟输出。细节见 [ARCHITECTURE.md](ARCHITECTURE.md) |
