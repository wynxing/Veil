# 等待过程与故障引导验收

## 产品行为与实现范围

“保持关闭”、辅助输出安装与启用、单屏及全部恢复、退出前恢复由同一显示操作线程串行处理。面板展示当前阶段、总等待时间和阶段等待时间；托盘在处理中显示忙碌状态。启用或安装辅助输出仍需明确确认，UAC 由 Windows 显示。关屏请求提交前可以取消；辅助程序正在执行时先等待其结束，不强杀。提交后由现有恢复协议处理“恢复全部”。磁盘会话协议仍为 v2。

虚拟路径未出现时，界面说明关屏请求尚未提交，并等待恢复与必要清理的明确结果。恢复或清理未确认时保留会话和恢复入口，不显示“已关闭”或允许正常退出。辅助程序超时但进程仍在运行时保留句柄，阻止新的关屏、安装和正常退出；恢复入口仍可用于处理已有会话。

本轮只改善等待交互、串行化与诊断。客户机器上辅助虚拟路径不出现的原因仍需客户日志和机旁复现定位。

## 日志与客户排查

- App 日志：`%TEMP%\Veil-app.log`。包含 `operation-start/end`、`operation-stage/end`、辅助程序启动／结束／超时和返回码。日志的时间戳为 Unix 秒。
- 会话日志：`%LOCALAPPDATA%\Veil\session-<id>\events.jsonl`，同目录的 `heartbeat.json`、`result.json`、`session.json` 可辅助判断恢复是否确认。`events.jsonl` 包含阶段事件和 `vdd-path-wait-end` 的活动路径、虚拟路径、已识别辅助路径数量。
- 客户反馈时保留出问题时间、操作方式、App 日志和对应会话目录；会话文件可能包含显示器标识，分享前先检查隐私信息。不要仅凭“未响应”或辅助程序返回 0 推断物理屏已经关闭。

## 离线验证

| 场景 | 通过条件 | 证据边界 |
| --- | --- | --- |
| 长等待与重复点击 | 工作线程等待时 UI 命令可立即入队；同一按钮不会重复提交 | 单元测试及代码检查，不等于实际 Windows 窗口交互 |
| 权限取消与等待中取消 | 取消确认后不启动辅助程序；取消信号先于排队命令生效，提交前不写关屏意图 | 模拟确认、辅助程序与显示拓扑 |
| 启用成功但无虚拟路径 | 记录路径数量和识别结果；不提交关屏意图，等待恢复和清理结果 | 模拟 CCD，无真实驱动诊断 |
| 提交后恢复、恢复失败、清理失败 | 恢复结果未确认不报成功；未确认活动物理输出时不禁用自有 VDD | 模拟恢复协议与拓扑 |
| 辅助程序超时后才退出 | 保留进程句柄，在其未退出时拦住新设备操作；退出后可重试 | 进程句柄模拟，不等于真实 UAC |

验证命令：`cargo test --manifest-path src/Cargo.toml --workspace --locked`、`cargo check --manifest-path src/Cargo.toml --workspace --all-targets --locked`。Windows CI 还运行 release 构建及离线安装包打包。通过测试只能证明模拟路径与构建，不代表真实 UAC、显示硬件或客户故障已修复。
