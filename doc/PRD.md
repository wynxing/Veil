# Veil 产品需求文档

版本：0.8
状态：最小应用开发中；第一组仅内屏保持关闭采用已签名 VDD 第二目标；关屏中睡眠唤醒后不自动再关
日期：2026-09-18

## 1. 产品定位与目标

Veil 是一个 Windows 屏幕开关管理工具，让用户独立控制各显示器的显示状态，并保持设定直到主动恢复。它不是全局熄屏快捷方式，也不把一次熄屏指令的成功等同于持续关闭能力已经成立。

核心价值是让用户清楚地决定哪块屏幕显示、哪块屏幕关闭，以及关闭状态何时结束。临时关闭与保持关闭是两种不同意图，必须分开检测、展示与执行。

目标用户是使用 Windows 笔记本或台式机，需要临时熄屏、持续关闭指定屏幕或独立管理多显示器的用户。

### 典型场景

| 场景 | 用户期望 |
| --- | --- |
| 短暂离开电脑 | 临时熄屏，回来后可以正常唤醒 |
| 不需要某块屏幕 | 指定屏幕保持关闭，直到主动恢复 |
| 多显示器工作 | 关闭其中一块，其他屏幕继续使用 |
| 后台任务运行 | 关闭屏幕；根据单独选择的睡眠策略决定是否保持系统运行 |

### 非目标

首版不包含自研显示驱动、复杂显示配置与配置档案、窗口布局精确迁移还原、跨平台支持或自研通信与画面传输能力。第一组仅内屏保持关闭依赖已签名虚拟目标，不能宣传成不依赖虚拟屏。不承诺在全部 Windows 设备上实现面板断电。

### 已对齐决策

2026-09-17 对齐结论如下。这些是产品边界，不是已验证能力。

**产品身份。** Veil 按屏幕独立管理显示状态。临时关闭允许随后被正常输入唤醒；保持关闭必须维持到用户主动恢复或明确的安全恢复。若目标硬件无法可靠保持关闭，应禁用该操作并说明原因，或收缩支持范围；不得用全局临时熄屏或黑色覆盖层冒充该能力。

**首版关屏成功标准。** 验收以「被选中的屏幕持续不显示桌面内容」为准，并由系统状态检查与物理观察共同确认。面板待机或断电是更优的物理结果，按设备记录为能力，不作为全部 Windows 设备的首版必达项。黑色画面（屏幕仍亮且仍参与桌面）不是关屏成功。停止桌面输出可以作为达到该标准的候选机制，但不等于面板已断电，由此引起的布局变化必须记录。API 返回成功不能单独作为验收通过。

**第一组验证硬件。** 第一组闭环在开发机上证明「仅笔记本内屏」的持续关闭与主动恢复。库存如下。控制能力以 [validation/redmi-book-14-2025-internal.md](validation/redmi-book-14-2025-internal.md) 为准，不得把未测项写成已兼容：

| 项 | 记录 |
| --- | --- |
| 计算机 | XIAOMI REDMI Book 14 2025(FHD+)，笔记本 |
| 系统 | Windows 11 家庭中文版，64 位，内部版本 26200 |
| GPU | Intel UHD Graphics，驱动 32.0.101.6733 |
| 物理显示器 | 内置面板 TM140VDXP02（`DISPLAY\TMA0813`），1920×1200，当前已连接且活动 |
| 验证用虚拟屏 | 已安装 Virtual Display Driver 25.7.23（`ROOT\DISPLAY\0000` / VDD by MTT）；单独枚举，不计入物理屏支持范围 |

单外接、内屏加外接、多外接仍属验证矩阵。本机当前未接入外接屏，这些拓扑标注未验证。仅内屏作为第一组目标，意味着最后一块可见屏与紧急恢复必须进入首次闭环，不能推迟到外接屏场景。

**已记录的仅内屏结果（2026-09-17）。** 能枚举这块内屏，亮屏下保存/恢复拓扑成立。`SC_MONITORPOWER` 会变成睡眠感黑屏，机旁感觉后台不会继续运行，且看门狗定时曾被墙钟拉长，不能当作「关屏且系统保持运行」。CCD `SetDisplayConfig` 停用最后一条物理路径校验返回 87，未 apply；当前已测 CCD 调用未实现仅内屏保持关闭，不得降级为临时关闭或黑窗；不能由错误 87 推导所有路线均不可能。

**已记录的虚拟屏辅助（安装前，2026-09-17）。** 见 [validation/redmi-book-14-2025-aux.md](validation/redmi-book-14-2025-aux.md)。当时无第二目标，探针因 `remainingActive=0` 拒绝 apply。安装后结果见下文「虚拟屏辅助实测」。

**第二轮复核（2026-09-17）。** 三组配套参数的原样拓扑校验均为 0，停用唯一内屏均为 87。Windows 事件确认历史 `SC_MONITORPOWER` 实验进入现代待机。独立恢复进程的亮屏定时恢复、软件注入快捷键消息链、父启动进程异常退出恢复已通过；它们不等于关屏后恢复验收。详见 [第二轮记录](validation/redmi-book-14-2025-revalidation.md)。

**虚拟屏辅助实测（2026-09-17 实跑，2026-09-18 续测）。** 已安装官方 VDD 25.7.23（`oem58.inf`，SignPath）。CCD 只停内屏、保留虚拟目标：15 秒系统检查与一次机旁观察通过（内屏熄灭，普通输入不唤醒，`Ctrl+Alt+Shift+F10` 恢复）；父进程崩溃后独立恢复进程仍能恢复；另一次 15 秒、一次 600 秒与 20×15 秒循环的系统检查通过，关屏期间采样均为 `activeInternal=0`。关屏期间禁用虚拟适配器后，保持关闭结束，内屏被点亮，保存的双路径拓扑无法回放。关屏中睡眠：Kernel-Power 506/507 与 Adaptive Connected Standby；唤醒后内屏亮起，保持关闭结束且未自动再关。第一次应用把 `execution-gap` 显示为未知，文案修正后操作者确认界面正常。这不是「仅第二屏幕」投影模式。详见 [虚拟屏辅助记录](validation/redmi-book-14-2025-vdd.md)。

**已对齐的实现路线（2026-09-18）。** 第一组硬件的保持关闭采用该 VDD 辅助机制。稳定性指：关屏前必须有活动虚拟目标且紧急热键注册成功；独立恢复进程在父进程退出后仍能恢复；虚拟目标消失或睡眠唤醒时结束保持关闭并重新识别屏幕，不跨睡眠自动再关；不写入持久显示配置；不跨重启自动关屏。最小应用见仓库 `app/`，不是安装包，也不扩大到未验证硬件。

## 2. 核心功能与优先级

以下为待实现的产品要求，不表示当前仓库已有对应功能。

| 优先级 | 功能 | 要求 |
| --- | --- | --- |
| P0 | 显示器识别与列表 | 展示可区分的名称、内置或外接类型、连接状态、当前状态和可用控制能力；无法识别的属性标记未知 |
| P0 | 按屏幕控制 | 对选定显示器发起开启、临时关闭或保持关闭；不可用操作展示具体原因 |
| P0 | 保持关闭 | 在支持的配置中维持所选屏幕不显示内容，直到用户主动解除；状态变化需重新检查 |
| P0 | 单屏恢复 | 解除该屏幕的关闭要求，使其重新可用，不解除其他屏幕的保持关闭状态 |
| P0 | 恢复全部屏幕 | 解除所有关闭要求，恢复当前仍连接屏幕的可用显示配置 |
| P0 | 紧急恢复 | 提供不依赖可见设置窗口的恢复入口，并在全屏关闭前检查恢复条件 |
| P0 | 状态反馈 | 区分用户要求、已确认状态、处理中、失败和未知，失败不得显示为已关闭 |
| P1 | 保持系统运行 | 提供独立、明确的防睡眠选项，默认不改变系统睡眠策略 |

首版至少应在第一组验证硬件上证明持续关闭与恢复的完整路径。支持范围由验证结果收敛，不通过黑色覆盖层冒充硬件关屏。

## 3. 状态规则与使用流程

### 状态含义

| 用户选择 | 行为 |
| --- | --- |
| 开启 | 解除该屏幕的关闭要求，并恢复其显示能力 |
| 临时关闭 | 执行一次关闭，允许后续正常唤醒；唤醒后更新状态，不反复强制关闭 |
| 保持关闭 | 记录持续关闭要求，正常输入不得被视为解除请求；只有主动恢复或明确的安全恢复策略可以结束该要求 |

“保持关闭”属于产品意图；是否能够在具体设备上实现，必须由能力检测与实测确认。无法可靠支持时禁用该操作并说明原因，不能悄悄降级为临时关闭。

### 正常操作

1. 用户打开界面，查看已连接显示器及各自可用操作。
2. 选择一块或多块屏幕及关闭方式。
3. 程序检查能力和恢复入口，保存切换前的必要显示配置。
4. 执行切换并检查结果，按屏幕呈现成功、失败或未知。
5. 用户通过仍可见的界面、托盘菜单或紧急恢复入口恢复显示。

关闭设置窗口仅隐藏界面，后台继续维持状态。托盘菜单提供打开界面、恢复全部屏幕和退出程序。正常退出程序时先解除关闭要求并尝试恢复显示；恢复失败时报告失败，不默默退出。后台异常终止适用异常恢复规则。

在可能关闭最后一块可见屏幕前，必须先具备经过验证的恢复入口。未具备时拒绝执行，并说明需要满足的条件。

### 恢复入口

- 常规入口：界面的单屏恢复、恢复全部按钮，以及托盘中的恢复全部操作。
- 紧急入口：全局快捷键（F12 被系统保留给调试器，故改用 F10），候选默认值为 `Ctrl + Alt + Shift + F10`。注册失败必须可见，不能声称该入口可用。
- 全局快捷键的桌面与会话适用范围需验证，不能将它视为所有异常下都有效的唯一保障。
- 恢复应优先使用操作前配置；连接设备变化时恢复可用配置，不盲目套用已失效的布局。

## 4. 异常与生命周期

以下是首版行为目标。恢复机制的进程划分和具体系统接口将在技术验证后确定。

| 事件 | 行为要求 | 待验证事项 |
| --- | --- | --- |
| 设置窗口关闭 | 后台保持用户设定 | 托盘生命周期与状态同步 |
| 普通键鼠输入 | 临时关闭允许唤醒；保持关闭不因此解除 | 唤醒来源、设备差异及是否出现短暂亮屏 |
| 控制操作失败 | 返回具体失败，重新读取状态，保留可用恢复入口 | 部分成功、驱动超时和状态检测可靠性 |
| 后台程序异常 | 安全恢复优先：独立恢复进程在父进程退出后点亮内屏并回放保存拓扑 | 本机父进程 `os._exit` 后热键恢复已通过；恢复进程自身崩溃仍不在可靠范围内 |
| 系统睡眠与唤醒 | 睡眠期间不执行控制；唤醒后重新识别屏幕。首版不跨睡眠自动再关 | 本机已测：唤醒后内屏亮起，未自动再关。第一次界面把中断标成未知，修正后复测通过。唤醒闪屏仍不能预先承诺消除 |
| 系统重启 | 首版默认不跨重启自动重新关闭屏幕；启动后重新读取实际状态 | 操作前配置的安全恢复及持久化拓扑影响 |
| 显示器拔出 | 标记断开，不对不存在的设备持续重试 | 设备标识的稳定性 |
| 显示器插入 | 新设备默认不继承关闭要求；同一运行期内能可靠识别的原设备可重新应用原要求 | 扩展坞、接口变更及重连识别 |
| 紧急恢复 | 解除全部保持关闭要求，尝试恢复所有已连接屏幕 | 单屏、多屏、仅内屏和配置变化后的恢复 |

安全恢复属于“保持关闭”的明确例外。程序不能在已经失去可靠控制能力时继续向用户保证状态有效，也不能承诺系统启动阶段或全部异常下始终不出现画面。

## 5. 技术边界与已选定路线

第一组仅内屏保持关闭已选定：已签名虚拟目标 + CCD 停用内屏。下表其余项仍是边界，不是全平台保证。

| 概念或候选方向 | 边界 |
| --- | --- |
| 停止桌面输出 | 使显示器不再参与桌面输出；不等于面板已经断电，可能影响桌面布局 |
| 面板断电或待机 | 依赖显示器、连接方式与硬件支持，需要实际检查关闭和重新开启能力 |
| 黑色画面 | 屏幕可能仍亮着且仍参与桌面；不作为关屏成功的替代标准 |
| Windows 显示配置接口 | 候选用于识别、修改和恢复显示拓扑；最后一块物理屏的处理需先验证 |
| 显示器电源控制 | 候选用于支持的设备；内置面板与外接显示器分别验证 |
| 虚拟显示器 | 第一组仅内屏保持关闭的必要辅助目标；使用已签名第三方驱动，不自研。虚拟屏单独枚举，不对用户提供保持关闭操作 |
| 状态维持与监护 | 需要核对实际状态、避免无界重试，并在切换前准备恢复；不能仅以主界面存活作为成功依据 |

系统运行与屏幕显示是不同状态。默认不修改用户电源计划，不以“关闭屏幕”保证下载、编译或其他任务不会被系统睡眠中断。若后续实现防睡眠功能，必须独立显示其是否启用以及何时解除。

## 6. 验收与技术验证

### 成功标准

首版功能验收看被选屏幕是否持续不显示桌面内容，而不是看面板是否普遍断电。每台设备仍须记录实际物理结果：停止输出、待机或断电、短暂亮屏、对其它显示器的影响。黑色覆盖层不得计入成功。

### 核心验收

1. 能区分已连接显示器，并展示各自支持的控制能力。
2. 在受支持配置中，选择屏幕保持关闭后，该屏幕持续不显示桌面内容，普通输入不会解除要求。
3. 未选屏幕继续可用，不被意外关闭；拓扑变化带来的布局调整需记录，不能承诺窗口位置完全不变。
4. 临时关闭后可正常唤醒，程序不会立即重新关闭。
5. 单屏恢复只解除目标屏幕的要求；恢复全部解除所有要求并使可恢复的已连接屏幕重新可用。
6. 关闭设置窗口后持续控制仍有效，用户能通过托盘或已验证的紧急入口恢复。
7. 不支持的操作、部分成功和恢复失败均有真实反馈，不显示虚假的成功状态。
8. 在目标测试硬件上连续完成 20 次关闭与恢复循环，无不可恢复的黑屏；记录硬件、系统、操作步骤与结果。

### 必须记录的验证矩阵

- 第一组闭环：上述 REDMI Book 14 2025 的仅笔记本内屏；通过前不扩大宣称范围。
- 后续矩阵：单外接屏、内屏加外接屏、多外接屏；本机未接入外接屏前标注未验证。
- 普通输入、设置窗口关闭、主程序崩溃、睡眠唤醒、重启、热插拔。
- 不同控制机制的实际表现：是否停止输出、是否待机或断电、是否短暂亮屏、是否影响其他显示器。
- 每组结果记录 Windows 版本、GPU 与驱动、显示器型号和连接方式；未测试配置标注未验证。
- 枚举结果中的虚拟显示器单独记录，不计入物理屏支持范围。

验收以系统状态检查与物理屏幕实际观察共同确认。API 返回成功不能单独证明屏幕已不显示桌面内容，也不能单独证明面板已关闭。没有覆盖全部矩阵时，只发布已验证的支持范围。

## 7. 实施阶段

1. **需求定义**：完成 PRD、README、仓库初始化，以及定位与范围对齐。
2. **技术验证**：纯原生仅内屏保持关闭不支持。VDD 辅助短时闭环、关屏下父进程崩溃恢复、10 分钟与 20 次循环、虚拟目标消失后的内屏命运、一次关屏中睡眠唤醒已记录。
3. **最小应用（当前）**：在本机已验证配置上实现物理屏列表、内屏保持关闭/恢复、托盘与 `Ctrl+Alt+Shift+F10`。操作者已完成两次短时保持关闭并用热键恢复。关屏中睡眠后内屏会亮、不自动再关；界面按重新识别结果展示，操作者已复测确认。虚拟目标缺失时拒绝关屏。不提供安装包。
4. **兼容性完善**：扩大硬件矩阵，再评估防睡眠等增强功能。

支持版本、设备范围和具体控制机制仍由技术验证补齐。没有实测证据时，不得宣称功能完成或硬件兼容。
