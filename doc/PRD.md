完整运行时、安装与界面设计见 [PRODUCT_DESIGN.md](PRODUCT_DESIGN.md)。实现栈见 [ARCHITECTURE.md](ARCHITECTURE.md)。机制证据见 [TECH_VALIDATION.md](TECH_VALIDATION.md) 与 `validation/`。本文是产品合同：用户要什么、首版做什么、什么算成功。未测项不得写成已兼容。

## 1. 定位与目标

Veil 是可公开分发的 Windows 屏幕保持关闭工具。用户按物理屏决定哪块关、哪块开，并保持到主动恢复。它不是全局熄屏快捷方式，也不把一次 API 成功当成持续关闭已经成立。

目标用户是 Windows 笔记本或台式机使用者：需要关掉一块或多块物理屏继续用留下的屏，或在没有外接屏时关掉笔记本屏幕。

### 典型场景

| 场景 | 用户期望 |
| --- | --- |
| 不需要某块屏 | 该物理屏保持关闭，直到在面板里恢复或按紧急热键 |
| 多显示器 | 可同时关多块，留下的物理屏继续可用 |
| 只有笔记本一块屏 | 安装应用时带上的辅助虚拟输出作为退路；若当时没装设备，面板里可以再装。允许关光全部物理屏 |
| 睡醒或重启 | 重启后全部按系统亮着；睡醒后尽量恢复仍有效的保持关闭，做不到则结束并说明 |

### 非目标（首版）

临时关闭、系统熄屏入口、自研显示驱动、把虚拟屏当作可关目标、跨重启自动再关、黑色覆盖层、精确还原窗口布局、跨平台、自研画面传输、不经确认静默安装驱动、启用测试签名。不承诺全部设备面板断电。不把实验室探针当作已发布产品。不把向日葵、GameViewer 等其它虚拟屏当退路。

### 关屏成功标准

被选中的物理屏持续不显示桌面内容，由系统状态检查与物理观察共同确认。普通键鼠不得解除保持关闭。黑色画面（屏仍亮且仍参与桌面）不是成功。停止桌面输出是候选机制，不等于面板已断电；布局变化与开关闪烁必须允许并记录。API 成功不能单独作为验收通过。

## 2. 首版功能

| 优先级 | 功能 | 要求 | 验收 |
| --- | --- | --- | --- |
| P0 | 物理屏列表 | 可区分名称、内置或外接、连接与已确认状态、此刻能否保持关闭 | 未测配置标未知，不列出虚拟屏 |
| P0 | 保持关闭 | 在能留下一条活动路径时维持所选物理屏不显示内容 | 见设计第 5 节；未通过的配置须禁用 |
| P0 | 单屏恢复 | 只解除该屏要求，其它保持关闭不变 | 设计目标；多路组合尚未闭环 |
| P0 | 恢复全部 | 解除全部要求，恢复仍连接且可恢复的物理屏 | 热键与托盘必须可用 |
| P0 | 紧急恢复 | 不依赖面板可见；关屏前热键必须注册成功 | 默认 `Ctrl+Alt+Shift+F10`；失败则拒绝关屏 |
| P0 | 状态反馈 | 区分要求、已确认、处理中、失败、未知 | 失败不得显示为已关闭 |
| P0 | 辅助虚拟输出 | 无第二物理屏且用户要关光物理屏时，启用已签名 MTT 辅助输出。安装应用时默认一起装设备；没有设备则可在面板确认后安装 | 设计已改；代码按 [安装计划](plans/2026-09-20-vdd-install.md) 尚未改完。须同意与 UAC，默认禁用设备 |
| P1 | 开机自启 | 默认关，面板可开；自启不等于跨重启再关屏 | 代码已有，尚未机旁验收 |
| P1 | 保持系统运行 | 独立防睡眠选项，默认不改电源计划 | 未做 |

没有第二活动目标、且找不到已校验辅助输出驱动包、也无法安装设备时，拒绝关掉最后一块物理屏，并说明原因。有驱动包或本机已有同一 MTT 设备时，应让用户安装或启用，不得只禁用按钮。不得降级为临时关闭或黑窗。

## 3. 使用规则

### 用户选择

| 选择 | 行为 |
| --- | --- |
| 开启 | 解除该物理屏的保持关闭，并恢复显示 |
| 保持关闭 | 记录持续关闭要求；普通输入不是解除 |

首版没有「临时关闭」。

### 日常操作

1. 用户启动程序后，托盘常驻；单击打开小面板。  
2. 面板只列物理屏。用户对某块选择保持关闭或恢复。  
3. 程序检查能力与恢复入口，保存切换前必要显示配置。  
4. 执行后按屏展示已关闭、失败或未知。  
5. 用户用面板、托盘「恢复全部」或紧急热键恢复。

关上面板不等于退出。右键托盘：打开面板、恢复全部、退出。正常退出须先恢复物理屏；失败则报告，不默默退出。

### 恢复入口

- 常规：面板单屏恢复、恢复全部、托盘恢复全部。  
- 紧急：`Ctrl+Alt+Shift+F10`。注册失败必须可见。  
- 人工兜底：`Win+Ctrl+Shift+B`，仍无画面再重启。  
- 优先回放操作前配置；设备已变则恢复当前可用配置。

## 4. 异常与生命周期

| 事件 | 行为要求 | 证据状态 |
| --- | --- | --- |
| 面板关闭 | 后台继续维持保持关闭 | 产品面板未做机旁 |
| 普通键鼠 | 不解除保持关闭 | 已测配置上成立 |
| 操作失败 | 具体原因，保留恢复入口 | 须在产品界面兑现 |
| 界面进程退出异常 | 独立恢复进程回放保存拓扑 | Python 探针 REDMI / P15 父进程退出已测；Rust 未机旁 |
| 恢复进程自身崩溃 | 不保证回放拓扑；面板必须结束会话并写明原因 | 拓扑回放仍排除。解绑与 disable 仅有单元测试，机旁未复测 |
| 睡眠唤醒 | 重新枚举；能留下活动路径则尝试再关，否则结束并说明 | Python REDMI：醒后亮起、未再关。Rust 睡醒尚未机旁执行 |
| 重启 | 不恢复关闭要求 | 设计已锁定 |
| 拔出 | 标记断开，不对其重试 | 未做产品级热插拔矩阵 |
| 插入 | 默认开启；同一运行期能认出的原设备可重新应用仍有效要求 | 未做 |
| 卸载 | 先恢复物理屏，再禁用并移除 Veil 清单里的辅助 VDD（含运行时接管的同一 MTT 实例） | 代码检查协议 v2 恢复结果；失败、未知或超时阻止驱动移除；机旁未做 |

程序在已失去可靠控制时不得继续声称状态有效。

## 5. 技术边界

| 概念 | 边界 |
| --- | --- |
| 停止桌面输出 | 首版机制；不等于面板断电，可能改布局、开关闪烁 |
| 面板断电 | 按设备记录，非必达 |
| 黑色画面 | 不算关屏成功 |
| CCD `SetDisplayConfig` | 识别、停用路径、恢复拓扑；不写入持久显示配置 |
| 辅助虚拟显示驱动 | 已签名第三方 MTT。随应用带文件，安装时或面板里装设备，按需启用；用户不可把它当功能屏来关 |
| 其它虚拟适配器 | 不进列表、不作退路 |
| 独立恢复进程 | 关屏的前提，不能只用界面进程存活当成功 |

系统睡眠与屏幕显示是不同状态。默认不修改电源计划。

## 6. 验收

1. 只列出物理屏，能力与原因真实。  
2. 受支持配置中，保持关闭后目标屏持续不显示桌面，普通输入不唤醒。  
3. 未选中的物理屏继续可用；布局变化与闪烁须记录，不承诺窗口位置不变。  
4. 单屏恢复只开目标屏；恢复全部与热键解除全部要求。  
5. 关掉面板后保持关闭仍有效。  
6. 失败与未知不得显示为已关闭。  
7. 目标硬件上 20 次关闭/恢复无不可恢复黑屏（已有配置见验证附录；新产品组合须重做）。  
8. 没有第二活动目标、且无法安装或启用辅助输出时，拒绝关最后一块物理屏。

发布范围 = 已验证配置。矩阵与哈希见验证文档，不把实验室日记写进产品口号。

1. **需求与设计**：PRD 与 [PRODUCT_DESIGN.md](PRODUCT_DESIGN.md) 已锁定公开形态；[ARCHITECTURE.md](ARCHITECTURE.md) 已锁定实现栈。  
2. **机制调研（可行性已收口）**：原生不能停最后一条路径；第二目标可以是实体外接或已签名 VDD。证据见 `validation/`。  
3. **公开产品实现（Rust，首版代码已齐，未发布）**：`src/` 为 Rust / egui，`installer/` 为 WiX。单屏恢复、卸载等待、睡醒单次再关已在代码与离线测试中。辅助输出改为「随应用装文件、安装时或面板装设备、已有 MTT 则接管」；实现计划见 [doc/plans/2026-09-20-vdd-install.md](plans/2026-09-20-vdd-install.md)。REDMI 短时只停内屏（`release` + 热键）已有系统检查 + 口头。仍待机旁：P15、Rust MSI 重装、长时 / 循环 / 睡醒 / 崩溃、面板点选、卸载闭环。  
4. **兼容与增强**：扩大硬件矩阵；再评估防睡眠等 P1。

没有实测证据时，不得宣称功能完成或硬件兼容。

## 可靠性修复补充（2026-09-19）

关屏、追加关闭或单屏恢复失败后，结束本轮全部关闭要求并尝试一次恢复。恢复失败时停止自动 APPLY，保留热键和“恢复全部”；用户再次操作才重试。正常退出和卸载都必须确认物理输出已恢复。细节、离线证据与待实测清单见 [可靠性修复验收](validation/reliability-v2.md)。本轮修改不继承旧版本实机验收结论。
