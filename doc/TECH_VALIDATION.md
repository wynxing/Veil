# Veil 技术验证协议

版本：0.13；日期：2026-09-19。机制可行性已收口，本协议仍用于复测与新产品组合验收。公开形态见 [PRODUCT_DESIGN.md](PRODUCT_DESIGN.md)，实现栈见 [ARCHITECTURE.md](ARCHITECTURE.md)，产品合同见 [PRD.md](PRD.md)。实验室探针仍在 `tools/display-probe/`，不是安装包。

已测睡眠（Python 探针，REDMI）：关屏中唤醒后内屏亮起，保持关闭结束，当时未自动再关。产品设计的「醒后尝试再关」在 Rust 上尚未机旁执行；公开版在该闭环通过前失败即停。

第一组：已签名 VDD 辅助只停内屏。第二组 COLORFUL P15 24 内屏加实体外接：Python 探针只停内屏短时、10 分钟、20 次循环与父进程崩溃独立恢复已记录。只停外屏短时闭环已记录。Rust 产品：REDMI 短时只停内屏（`release` + 热键）有系统检查 + 口头，见 [REDMI Rust](validation/redmi-book-14-2025-rust.md)；P15 尚未执行，见 [P15 Rust](validation/colorful-p15-24-rust.md)。产品门禁不把第三方虚拟屏当第二目标。

目标按硬件组分列。第一组：在 REDMI Book 14 2025 上，不接实体外屏，让内屏持续不显示桌面。第二组：在 COLORFUL P15 24 的扩展桌面上，用原生 CCD 停一块物理屏、留下另一块。不把黑窗算作关闭，不承诺面板断电。不得把第一组 VDD 结论写进第二组。

## 路线与已知事实

明确区分三类配置：**纯原生仅内屏**；**仅物理内屏＋虚拟目标**；**纯原生内屏＋实体外接**。虚拟目标路线引入驱动依赖，不能宣传成不依赖虚拟屏。第二组实验室走第三条，不安装额外虚拟屏。公开产品将随安装器带上已签名 VDD 并按需启用，见 [PRODUCT_DESIGN.md](PRODUCT_DESIGN.md)；那不是把本组 P15 结论改写成「已装 VDD」。

- 纯原生 CCD：对 basic、virtual、refresh 三组配套参数分别查询并校验。原样拓扑为对照，清除内屏 ACTIVE 为实验。不把参数错误 87 推导为所有技术路线不可能。
- 临时熄屏：`SC_MONITORPOWER` 仅作为电源行为诊断。已有 Windows 电源日志明确记录该命令导致新型待机；其持续性和后台运行不满足当前目标。
- 虚拟屏辅助：原生未通过后，采用已签名驱动提供第二活动目标，再只停内屏。安装前检查来源、签名、设备基线、卸载路径，不启用测试签名，不安装未签名替代品。

第一组结果见 [虚拟屏辅助记录](validation/redmi-book-14-2025-vdd.md)。[第二轮复核](validation/redmi-book-14-2025-revalidation.md) 与前两份报告保留为安装前历史。第二组 Python 探针见 [P15 外接记录](validation/colorful-p15-24-aux.md)。payload 核对见 [安装器 payload](validation/installer-payload.md)。

## 执行门槛

1. 接电、开盖、机旁有人；记录实际物理观察，不从 API 返回值猜测画面。
2. 保存拓扑，完成亮屏定时恢复与实际按键恢复预检。快捷键为 `Ctrl+Alt+Shift+F10`，注册失败禁止关屏。
3. 独立恢复进程确认就绪后才启动切换；首次 15 秒。实验不写入持久显示配置。
4. 诊断允许零活动路径 VALIDATE；实际停用命令仍要求至少留下一个活动目标。纯原生三组已失败时不强行 apply。
5. 失败、拓扑改变、超时或进程异常后停止，检查恢复结果后重新预检。不能以看门狗启动成功代替恢复已验证。

计时器与快捷键依赖系统调度和桌面会话。S0 待机、驱动阻塞或恢复进程自身崩溃时无绝对保证；人工兜底为 `Win+Ctrl+Shift+B`，仍无画面再重启。不能反复冒险重跑恢复失败的实验。

## 实验顺序与证据

1. 收集系统／GPU／驱动／显示路径／供电／电源策略基线，执行三组不关屏参数校验。
2. 亮屏定时恢复、快捷键恢复；自动注入按键只证明消息链，不替代机旁按键验收。
3. 需要时安装签名虚拟驱动，确认一块虚拟目标活动；重新保存拓扑和预检。
4. 15 秒内屏停用、普通键鼠输入、主动恢复及父控制进程异常恢复；逐次观察内屏、背光、闪烁与布局。
5. 短时闭环通过后才做 10 分钟独立后台任务验证、20 次关闭恢复循环。
6. 虚拟目标消失、一次睡眠唤醒单独测试；当前探针遇到异常拓扑或执行间隙优先恢复，不承诺自动重建保持关闭或消除唤醒闪屏。本机一次关屏中睡眠已记录。

每步记为通过、失败、未执行或证据不足。收集 API 参数和错误码、独立进程工作计数及时间戳、Windows 电源事件和机旁观察。系统检查与物理观察共同通过才算功能通过；缺少机旁观察不得宣称成功。

工具和命令见 [探针说明](../tools/display-probe/README.md)。原始证据留在主仓库 `.git/veil-validation-日期/`，不提交设备实例与拓扑原始字节；仓库提交可复核的摘要、版本、哈希与结果。
